# Contributing

## Commit messages

Использую [Conventional Commits](https://habr.com/ru/articles/867012/?ysclid=mudr9c214b662049023):

- `feat(scope): ...` — новая функциональность
- `fix(scope): ...` — исправление бага
- `docs: ...` — документация
- `chore: ...` — рутина (зависимости, конфиги)
- `refactor: ...` — рефакторинг без изменения поведения
- `test: ...` — тесты

## Branches

- `main` — стабильная ветка.
- `feat/<short-name>` — новая функциональность.
- `fix/<short-name>` — исправление бага.
- `docs/<short-name>` — документация.
- `refactor/<short-name>` — рефакторинг.
- `chore/<short-name>` — рутина (конфиги, зависимости).

## Workflow

- Делаю изменения небольшими логическими шагами.
- Каждый шаг — отдельный коммит.
- Перед коммитом проверяю `git status` — не попало ли лишнее.
- Пушить можно несколько коммитов одним `git push`.
- Инфраструктурные правки (конфиги, документация, Taskfile) — прямо в `main`.
- Новые фичи — через ветку `feat/<name>`.

## Tools

- **Task** — `task --list` покажет доступные команды.
- **golangci-lint** — конфиг в `.golangci.yml`.
- **gofumpt, gci** — форматирование кода.
- **go test -race** — тесты с детектором гонок.

Перед пушем: `task all`.
